# 稳举：实现思路与 Skill 复盘

## 1. 产品怎么收窄

先定「做什么」，再写代码。

用户原话可以收成一句话：

> 本地 PWA 健身清单。点一下勾上。每个动作能看图和要领。不要后端。

中间有几次收窄，避免做成大 App：

| 曾经可能做成 | 最后做成 |
| --- | --- |
| 打卡墙 / 连续天数 / 统计 | 只做 checklist |
| 账号 + 服务器数据库 | IndexedDB + localStorage |
| 可增删动作的训练系统 | 海报里的 A/B/C 固定计划 |
| 自动周期加重量 | 12 周只读参考 |

海报是内容源，不是装饰。8 张图拆成：

- 封面 / 总览 → 计划页
- A / B / C 日 → 今日清单 + 要领抽屉
- 12 周 / 目标 → 计划页只读
- 抱持 6 步 → 独立「要领」页，不进每日勾选

产品名：**稳举**。主题：把喜欢的人稳稳举起来。

## 2. 实现思路（先数据，再页面）

思路不是「先搭漂亮页面」，而是：

```
海报理解 → 写成 需求.md → 训练数据结构化 → 三个页面读同一份数据 → 勾选单独持久化
```

### 2.1 数据是唯一真相

`src/data/program.ts` 里写死：

- 三个训练日、每个动作的组数、肌群、要领、错误
- 每周安排、12 周阶段、目标重量
- 抱持步骤和禁止项
- 海报路径

页面只读这份数据，不在 JSX 里再抄一套文案。以后改组数，只改这一个文件。

### 2.2 页面按「用户一天怎么用」拆

```
今日 /          勾选今天的动作，点开要领
计划 /plan      看一周怎么排、12 周怎么进
要领 /guide     看怎么抱、什么不要做
```

底栏 3 个 Tab，不藏导航。这是手机 App 的常见一级结构。

### 2.3 组件各管一件事

| 文件 | 只做什么 |
| --- | --- |
| `TodayPage` | 把日期、日切换、清单、抽屉拼起来 |
| `DaySwitcher` | A/B/C 切换 |
| `ExerciseRow` | 一行：左边勾，右边打开要领 |
| `ExerciseSheet` | 底部抽屉，展示海报 + 要点 |
| `PlanPage` / `GuidePage` | 只读内容 |
| `useChecklist` | 勾选状态 |
| `useTrainingDay` | 今天建议哪一练 |
| `lib/db.ts` | 读写本地存储 |

对应 React 习惯：**页面编排，组件展示，Hook 管状态，纯函数管数据。**

和 Vue 的对应：

| Vue | React（本项目） |
| --- | --- |
| `ref` / `reactive` | `useState` |
| `computed` | `useMemo`（今日完成数） |
| `watch` 写存储 | `toggle` 里直接 `saveChecks` |
| `onMounted` 读存储 | `useEffect` 按日期加载 |
| 受控勾选 | `checked={checks[id]}` + `onClick` |

### 2.4 存储为什么两份都写

需求是「无后端，刷新不丢」。勾选量很小，但用户给过两种选择：localStorage 或 IndexedDB。

最后策略：

- **先写 localStorage**：同步、简单、一定看得到
- **再写 IndexedDB**：给以后存更多记录留口子
- **读的时候**：IndexedDB 有值用它，否则用 localStorage

勾选主键是 `日期 + 动作 id`，例如：

```json
{ "2026-09-17": { "a-squat": true, "c-goblet": false } }
```

不是「终身只勾一次」，换自然日就是新的一天。

建议日规则写在数据层：周一 A、周三 B、周六 C，其余休息可自选。选过的日存在 `localStorage` 的 `wenju-selected-day`。

### 2.5 视觉从哪来

不另做一套通用后台风。颜色、夜景、粉色标题跟海报走。底栏用半透明 + 模糊，接近手机 App 的 tab bar，而不是网页 footer。

勾选热区单独做大按钮（约 44px+），和「打开要领」分开，避免点勾却打开抽屉。

## 4. 用到的 Skill 和它们解决了什么

Skill 不是「自动写完项目」，而是 **给 Agent 一套专项手册**。这次真正用上的：

### 4.1 已安装到本项目

| Skill | 装在哪 | 这次怎么用 |
| --- | --- | --- |
| [apple-design](https://github.com/dickwu/apple-design-skill) | `.agents/skills/apple-design/` | 底栏当导航不当按钮；清单行「勾选」和「打开详情」分开；抽屉用 sheet；深色对比和约 44px 热区 |

安装命令：

```bash
npx skills add dickwu/apple-design-skill -a cursor -s apple-design -y
```

评审时它要求先读 HIG 再给意见，主要看过：`tab-bars.md`、`lists-and-tables.md`，以及设计原则里的简洁、熟悉、可点。

### 4.2 对话里参考过、但没装进本项目

| Skill | 作用 | 为什么没装 |
| --- | --- | --- |
| find-skills | 搜索生态里现成的设计 / 产品计划 skill | 只用来选型 |
| frontend-design / web-design-guidelines | 更偏通用 Web UI | 这个产品要跟海报走 Apple 手感 |
| to-prd / writing-plans / PLAID | 写 PRD、拆开发计划 | 需求已经足够小，直接写 `需求.md` 再做 |
| vue-best-practices / vue | 组件边界、composable | 前期准备用 Vue；你后来明确要 React，只保留「拆组件 + 抽 hook」这个思路 |

### 4.3 全局规则，不是 skill 包

`AGENTS.md`（老师模式）约束了这次怎么合作：

- 先判断模式：前期是产品理解，后来是「直接开发」
- 学习时不先甩完整代码；你说「给我实现 / 用 React」之后才写全量
- Vue → React 要对照着讲，不假装你会的还是 Vue 写法
- 每段不超过太多知识点

### 4.4 浏览器验证

实现后用 Browser Use 打开本地页，走了主路径：

1. 今日清单能出来，星期建议正确
2. 点圆圈，进度 0/6 → 1/6
3. 刷新后勾还在
4. 点「要领」弹出对应动作
5. `/plan`、`/guide` 标题和内容正确

这不是 skill 包，但是实现闭环的一步：UI 改完必须点过，不能只看截图。

## 5. 关键决策（以后改需求时对照）

1. **React 而不是 Vue**：你明确要求。熟悉的 Vue 思维仍然能用，只是 API 换了。
2. **数据写死，不做成 CMS**：动作来自固定海报，做成可编辑后台会超范围。
3. **抱持不进今日清单**：海报自己写了前 8 周不要真人测试。
4. **PWA**：给「加到主屏、离线还能打开」留口，不先做推送和后台同步。
5. **双写存储**：勾选丢失比多写一次更糟。

## 6. 学习时可以怎么看代码

建议按这个顺序读，每次只问一个问题：

1. `需求.md`：产品边界在哪
2. `src/data/program.ts`：一天有哪些动作
3. `TodayPage.tsx`：页面怎么把数据和勾选拼起来
4. `useChecklist.ts`：勾选状态从哪来、点了去哪
5. `lib/db.ts`：刷新为什么还在
6. `ExerciseRow.tsx`：为什么勾选和要领是两个按钮

对照练习：用 Vue 的 `ref` + `computed` 在纸上改写 `useChecklist`，不要先看答案。
