# 稳举：从想法到 WorkBuddy 上线

这份文档记的是**流程**，不是功能说明书。

- 产品边界看 [需求.md](../需求.md)
- 实现思路和 Skill 看 [实现总结.md](./实现总结.md)
- 对话流水看 [log.md](../log.md)

线上地址：https://wenju-fitness.app.workbuddy.host/

---

## 0. 一条线看完

```
海报想法
  → 收窄成「本地 checklist PWA」
  → 写成 需求.md
  → React + Vite 实现，数据写死在 program.ts
  → 本地 localhost:5173 点过主路径
  → npm run build 得到 dist/
  → 把构建产物交给 WorkBuddy 托管
  → 工作台拷一份到 site-release/ 上线
  → 发现刷新 /plan 会 404
  → 源码改 HashRouter + 相对路径，修手机输入
  → 重新 build，再同步发布
```

核心原则：**源码进 Git；构建产物不进 Git；线上只跑打包结果。**

---

## 1. 想法：先收窄，再动手

起点不是「做个健身 App」，而是海报上的一句话：

> 把喜欢的人稳稳举起来。

中间几次明确 **不做**：

| 曾经可能做成 | 为什么砍掉 |
| --- | --- |
| 打卡墙 / 连续天数 / GitHub 热力图 | 产品只要清单，不要成绩单 |
| 账号 + 后端 | 个人用，数据放这台设备就够 |
| 可增删动作 | 计划来自固定海报 |
| 「我的」统计页 | 超出 checklist |

收成一句话之后才写 `需求.md`，再写代码。海报是内容源：A/B/C 日进今日清单，抱持教程单独进「要领」页，前 8 周不进每日勾选。

## 2. 实现：先数据，再页面，再加体验

### 2.1 第一刀：能勾、能看要领

技术栈定成 **React 19 + TypeScript + Vite PWA**，无后端。

```
program.ts     训练日、动作、海报路径（唯一真相）
useChecklist   勾选
useTrainingDay 今天建议练哪一天
Today / Plan / Guide   三个 Tab
```

勾选先按天存，后来改成**按自然周**（周一 key）。重量和组间秒数另存，下周一只清勾选。

### 2.2 后来加上的（都是用的时候才要）

| 批次 | 加了什么 |
| --- | --- |
| 媒体 | 海报 1–9 轮播、点开放大 |
| 反馈 | 一日 6/6 悟空竖拇指；一周 A+B+C 布尔玛亲贝吉塔 |
| 要领 | 每动作示范图、肌群图、呼吸 |
| 教程 | 正面抱起 + 背对平举（姿势改了多轮，最后用你指定的图） |
| 训练 | 每动作公斤/磅、组间倒计时（声音 + 通知 + 震动） |
| 器械 | 计划页勾选本馆有什么，清单自动换替代；要领提示被换掉那条的上次重量 |
| 体验 | 手机数字框删完还能重填 |

### 2.3 本地怎么确认「能用」

```bash
npm install
npm run dev
```

打开 http://localhost:5173/ ，至少走过：

1. 今日清单出来，能切换 A/B/C
2. 点圆圈，刷新勾还在
3. 点要领，能改重量、能开休息
4. 底栏进计划、要领，再回来

只看截图不够。PWA 加到手机主屏后，还要再点一遍输入和通知。

## 3. 打包：线上吃的是 dist，不是 src

```bash
npm run build
```

Vite 把 React 编成静态文件，输出在 `dist/`：

```
dist/
├── index.html
├── manifest.webmanifest
├── assets/          带 hash 的 JS / CSS
├── posters/
├── exercises/
├── muscles/
└── icons/
```

`dist/` 已在 `.gitignore`。仓库只保证：**有源码就能重新打出这一包。**

静态托管的本质：服务器只提供文件，没有 Node 后端。稳举正好是这种应用。

---

## 4. WorkBuddy 怎么上线

当时的约定是：**不改业务代码，用已经打好的包部署。**

实际发生的事：

1. 交出 `WenJu-main.zip` / `dist.zip`（或仓库里的构建产物）
2. 工作台搭建师用静态托管挂到  
   `https://wenju-fitness.app.workbuddy.host/`
3. 为了不碰 `src/` 和你本地的 `dist/`，把发布副本拷到项目里的 `site-release/`
4. 实测：首页、JS/CSS、海报、manifest 都是 200

三个目录不要混：

| 目录 | 是什么 | 进 Git 吗 |
| --- | --- | --- |
| `src/` | 你改功能的地方 | 要 |
| `dist/` | `npm run build` 的输出 | 不要（已忽略） |
| `site-release/` | 工作台用来上线的 `dist` 拷贝 | 不要（已忽略） |

更新线上，不要手改 `site-release` 里的 JS。正确顺序：

```
改 src → 本地验证 → npm run build → 把新的 dist 同步给 WorkBuddy / 覆盖 site-release → 发布
```

在工作台里：设置 → 数据管理 → 应用，可管理这个站点。

## 5. 上线后才暴露的两件事

### 5.1 刷新「计划」变成 404

静态托管没有 `plan` 这个文件。

- 从首页点 Tab：React 在浏览器里换页，不向服务器要 `/plan` → 正常
- 在 `/plan` 刷新，或把这个链接发给别人 → 服务器找文件 → 404

这是 **History 路由 + 静态托管、又没配回退** 的典型问题，和 Vue 的 `createWebHistory` 没配 `try_files` 一样。

后来源码改成了 `HashRouter`，地址变成 `/#/plan`，刷新也先打到 `index.html`。  
`vite.config.ts` 里 `base: './'`，图片改成相对路径，子路径托管也不会裂图。

两种修法都可以，这次选了 Hash，因为 WorkBuddy 这种托管不一定能配 Nginx 回退：

| 做法 | 结果 |
| --- | --- |
| Hash 路由（已做） | 链接带 `#`，任何静态托管都能刷新 |
| 托管把所有路径回退到 `index.html` | URL 仍是 `/plan`，要托管支持 |

注意：线上若还是旧包，直链 `/plan` 仍会 404。要以**重新部署后的构建**为准，不是只改了本地 `src`。

### 5.2 手机上数字删完输不进去

受控的 `type="number"` 在 iPhone 上：删空立刻被写回 `90`，键盘和框对不上。  
改成文本草稿，失焦再收成数字。加到主屏的旧 PWA 要硬刷新或重装才会拿到新包。

## 6. 以后你自己走一遍（最短清单）

1. 改 `src/` 或 `需求.md`，功能先在本地 `npm run dev` 点过
2. `npm run build`，看 `dist/index.html` 是否是新 hash 文件名
3. 把新 `dist/` 交给 WorkBuddy（或覆盖 `site-release/` 再让工作台发布）
4. 打开线上首页，再试 `/#/plan`、`/#/guide` 刷新
5. 手机加到主屏的，必要时删图标重加，避免旧 Service Worker

Git 只提交源码和文档。`site-release`、`dist` 出现在 `git status` 里，说明忽略规则失效了。

## 7. 和 Vue 对照（方便记）

| 这次遇到的 | Vue 里的同类事 |
| --- | --- |
| `program.ts` 一份数据 | 不要在页面和 store 各抄一份 |
| `HashRouter` | `createWebHashHistory()` |
| 未配回退的 History | `createWebHistory()` + 静态机没 `try_files` |
| `dist/` | `vite build` 的输出目录 |
| `site-release/` | 把 `dist` 拷到服务器的那一层 |

---

## 8. 这次流程里真正值钱的决策

1. **先写边界再写代码**：没有热力图、没有账号，所以能静态上线。
2. **数据和勾选分开**：周重置清勾选，不清重量。
3. **上线用构建产物，不用源码目录**：WorkBuddy 当静态站即可。
4. **静态站的路由要按托管能力选**：不能配回退就用 Hash。
5. **真机输入和通知，本地桌面测不全**：手机删数字、后台计时，要在真机上看。
